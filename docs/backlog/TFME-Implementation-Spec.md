# Tileable Favorites Menu Extended（TFME）实施规格

> 版本：v1.0 · 日期：2026-11-19  
> 目标项目：[rainymidnight/tileable-favorites-menu](https://github.com/rainymidnight/tileable-favorites-menu)  
> 工作方式：从用户的 Fork 检出项目，优先使用仓库提供的 `scripts/Build-Debug.ps1` 验证本机基线。Release 构建使用仓库的 CMake 预设。
> **约束：本文仅规定功能、操作语义、边界条件和验收标准，不规定类、字段、序列化格式、表结构或具体数据结构。执行者必须检查源码并自行选择实现方案。**

## 0. 目标与边界

本项目扩展 Tileable Favorites Menu（TFM）的鼠标优先网格收藏界面，使其满足：

- 玩家仍通过 Skyrim 原生收藏行为把武器、护甲、药水、毒药、法术、卷轴、杂项、龙吼等加入面板；鼠标快速选择/使用是第一优先级。
- 默认每个新 Tile 占 **1×1 最小网格单元**，不再默认铺大；网格密度、整个窗口的位置/尺寸均可调。
- Tile 可自由移动、按“右键拖动方向与距离”伸缩、通过拖至另一个 Tile 内边界附近“模仿”其尺寸。
- 全局固定区域（Global）与随页切换区域（Page）共享**同一张网格**，通过拖选单元格划分，而非固定分成上下两个小窗口。
- Page 支持分类规则、自动放置/排序、分页及自动连续扩页；Global 不自动扩页。
- 内部允许一组页面由一个起始页及若干连续续页构成，但界面**禁止出现“主组”“衍生组”“扩展组”等内部术语**，应仅通过分类图标、页点、间隔/连续性表达关联。
- 不允许为腾空间悄悄删除项目、重写玩家收藏状态、覆盖其他 Tile 或损坏存档。

### 实施原则

1. **可预测**：正常使用时点击就是使用；编辑操作必须达到明确的手势门槛。
2. **手动优先**：用户自己摆过的位置不会被日常自动排序随意改写。
3. **保持原版特性**：保留 TFM 已有的收藏接入、鼠标直接选择/装备、图标/预览等能力，除非某项明确与新功能冲突并已处理迁移。

## 1. 上游基线与执行前核对

截至文档撰写时，上游公开 README 说明：TFM 是 vanilla/SkyUI 收藏列表的替代界面；源码仓库有 `src`、`flash`、`package`、`external`、`cmake` 等目录；使用 VS2022、CMake、Ninja、vcpkg；`cmake --preset release` 和 `cmake --build --preset release` 构建 DLL。根目录 CMake 使用 `OUTPUT_FOLDER` 可选参数输出模组目录。源码主版本显示 1.0.6。**这些是基线信息，不保证 Fork 创建后没有更新。**

执行者开始修改前必须：

- 核对 Fork 的默认分支、基线 commit、许可文件、已有未解决问题，并建立独立工作分支。
- 完整浏览 C++/SKSE、Scaleform/Flash、菜单输入拦截、布局、配置、收藏同步、持久化、打包资源路径；不要凭 README 推断 Flash 是否需要额外编译。
- 在**未改任何代码**的情况下完成 Release 基线构建，并尽可能在用户的测试环境验证原版运行。
- 列出当前交互与新交互的冲突：尤其是 Skyrim 默认 `Q` 收藏菜单键、`E` 激活键、右键原有语义、菜单暂停和鼠标输入占用。

## 2. 网格与窗口

### 2.1 最小单元与新增 Tile

- 新收藏项目默认 `1×1`；不再默认采用最大 Tile。
- 一个 Tile 在任意时刻占据**网格对齐的完整矩形**，不能悬浮在半格位置、产生重叠或跨区域。
- 可编辑最小单元的显示尺寸/密度；可调整行列数量，窗口的位置、总宽高/屏幕占比，以及必要的间距和边距。
- 行列数和最小单元尺寸应可以独立控制。若用户改变窗口尺寸，提供明确的网格自适应选项，不能未经说明偷偷重排。
- 小屏、4K、高 DPI、超宽屏、UI 缩放变化后文字/图标应保持可用。

### 2.2 窗口范围

- 面板**不强制占满全屏**；支持调整位置、调整宽高、保存布局；可用百分比或像素形式呈现设置（由执行者评估 UX）。
- 鼠标不能因为窗口缩小而无法点到某些 Tile；超出可用区域时执行统一安置规则。
- 显示窗口与分区网格的变更可预览、取消和撤销。

## 3. Tile 编辑交互

### 3.1 模式

- **使用模式**：左键快速选中/装备/使用（沿用原本 TFM/Skyrim 可行语义），不露出编辑控件，不因点击产生拖拽重排；键盘和鼠标均应响应迅速。
- 此时，允许左键拖动 Tile、右键拖动缩放、尺寸模仿。
- 手势优先级需与原模组的右键和其他菜单行为隔离；短暂点击、鼠标轻微抖动不可误触缩放或使用。
- **编辑模式**：修改区域掩码、排序和页面设置；需有清晰可见的编辑状态及退出方法。


### 3.2 右键按位移伸缩（用户指定）

- 不依赖鼠标精确命中 Tile 边缘或角上的小把手：**在 Tile 内任意位置按住右键，向某方向拖过 N 个相邻网格单位，即朝该方向增加 N 单位的覆盖范围**。
- 向左伸左边、向右伸右边、向上伸上边、向下伸下边；斜向拖动允许同时按水平、竖直位移扩展。结果始终是网格对齐矩形。
- 位移与单元格跳变应存在合理阈值/滞回，避免鼠标轻抖导致尺寸反复变化；实时显示预览尺寸、范围和冲突反馈；**松开后才提交**。
- 当扩展触及网格边缘、Global/Page 类型不同的格子或其他 Tile 时，不能重叠/穿区；显示失败原因和合法预览，不得悄悄移动/删除其他手动 Tile。
- **缩小交互仍需实现**，但用户尚未指定最终手势。可将 `Shift + 右键拖动` 沿相应边收缩作为候选默认，执行者须检验其直观性、与 Skyrim 输入是否冲突，并把决定记录在实现说明中；同时支持重置到 `1×1` 的显式命令。

### 3.3 尺寸模仿

- 在编辑模式中，**将 Tile A 用左键拖到 Tile B 的内侧边缘附近**，触发“模仿 B 的尺寸”候选状态。感应区域应足够宽、不要求像素级精准命中。
- 预览 A 将具有和 B 相同的网格宽高；只复制**尺寸**，不复制物品、收藏、所属分类或 B 的位置。
- B 必须显著高亮或显示对应反馈，候选应有必要的停留/阈值，以避免普通交换位置/拖动被误认为模仿；松开确认。
- 最终位置仍需满足合法矩形和占用规则；如果无法放置，依统一安置规则处理，且允许取消/撤销。

## 4. 同一网格上的 Global 与 Page

### 4.1 任意区域掩码

- Global（始终显示）和 Page（仅当前页显示）**共享一个网格**；可逐单元格指定归属。
- 编辑模式下，通过**长按、拖动矩形框选一批单元格**，他们之中的每一个单元格分别独立地进行切换（ Global 与 Page 之间切换）；支持多次选择拼成 L 形、不连续等任意形状。
- 可以提供逐格修改作为辅助，但不能把逐格点选作为唯一方式。
- 区域掩码对所有页面生效；切页时 Global 的位置和 Tile 不变，只换 Page 格上的内容。
- Tile 不得跨越 Global/Page 边界，即便区域是凹形或不连续，也只能占用其内部完整矩形。
- 编辑区域时要预览将受影响的 Tile，并在提交时使用统一安置器；不允许悄然丢弃冲突 Tile。

### 4.2 Global 行为

- Global 是 **空间属性（单元格属性）** 而非物品类型：任何可收藏项目都能由用户放进去。
- 每个 Global 位置在所有页面共用；Global 不创建新页。
- Global 区域发生溢出时，**把该 Tile 当作新收藏项目重新分配**，按类型到页面组的映射进入相应 Page 组；不丢失收藏状态。
- 手工从 Page 拖向 Global 时，交互允许拖放预览；若目标不可安置，结果必须明确且可撤销，不可静默覆盖别的 Tile。

## 5. 分页、自动分类与导航

### 5.1 页面组与自动续页

- 用户配置的单位是**页面分类/页面组**，可自由创建、重命名、调整顺序、选择图标；不是被固定死的武器轮盘/魔法轮盘。
- 一个页面组可以因容量不足或者用户自己创建而拥有任意多个连续页面；这些页面在导航顺序中始终相邻，整体移动时一同移动。
- 自动生成的新页面始终添加到**该组最后一页之后、下一组之前**，不插到无关组中；新增页面与原组共享分类规则和 Global 掩码。
- **最终 UI 不应出现“主组”“衍生组”“扩展组”等字样**。建议通过组图标 + 多个页点 + 组间适度间隔/分隔符表示“这些页属于同一组”。
- 用户点击**组图标**进入该组第一页，点击某个页点进入精确页面；页面过多时需避免导航条无限变宽（可滚动、折叠或按需省略，具体 UX 自定）。
- 非空页面不可被自动删除；只有完全空白、系统自动创建且用户未编辑过的末尾页面才可自动回收，或者由用户显式整理。

### 5.2 切页

- 菜单打开时 `Q` 上一页、`E` 下一页，按**实际页面序列**逐页跳转；点击页面指示器也能切换。
- 标签可设在窗口顶部/底部/侧边或浮动位置，能够用鼠标直接选择；是否循环到首尾作为可配置选项。
- 必须处理原版 `Q`（收藏菜单）与 `E`（激活）键冲突：菜单内翻页不得同时关闭菜单、激活错误物品或让按键穿透到游戏；关闭菜单后不劫持正常游戏按键；Tab 关闭菜单的功能需要保留。
- 切页只改变 Page 内容，Global 区域保持原样；支持鼠标快捷操作，不强制先经过轮盘悬停再松键确认。

### 5.3 “默认去处”分类规则

- 至少识别这些分类：**武器与护甲、药水、毒药、法术、卷轴、杂项、龙吼**。必要时执行者可以细分判别，但默认 UI 应有这些入口。
- 为每个类型设置**默认页面组**；多个类型可映射到同一个组（例如法术、卷轴、龙吼 → 魔法；药水、毒药 → 消耗品）。
- 一个类型也可以映射到多个页面。根据页面排序的前后，找到第一个有空的页面放在。
- 新收藏时根据规则决定所属页面；页面由分配算法自动选择，用户不需要设置“放第几页”。
- 自动分类只发生在之前没有定位的组件被加入。这意味着用户手工将某项目移到别的组/Global 后，自动分类不会在下一次刷新中把它搬回。
- 当分类映射必须时刻保持有效。这意味着在页面被删除时，需要保证每一个分类至少有一个被指定的页面，如果没有了，默认放到第一个页面。

### 5.4 自动排序

- 支持页面级自动排序（至少包括名称、类型，以及可从游戏可靠获得的可比较属性）；可恢复原始/手动顺序。
- 新项目按分类和指定排序规则自动放置，不要求用户逐件拖入。
- **自动项目与手动固定项目须区别对待**：手工移动、改大小、尺寸模仿及明确固定的 Tile 不得在普通新增/刷新时被自动排序打乱。
- 对自动 Tile 可在必要时重新排列；显式“整理当前页/组”须先预览影响并支持撤销；不要用运行时刷新触发全局重排。

## 6. 统一溢出机制（以本节为最终规则）

所有新增或可能改变占用的事件——收藏增加/移除、拖动、尺寸调整、区域重新指定、网格缩小、排序、页面切换引起的布局合法性重检——应通过**一致的、可测试的合法性检查与安置流程**。

### 6.1 同一区域优先

对于需要安置的 Tile：

1. 如原位置及**原实际尺寸**仍合法，优先保持原样。
2. 否则，先在**当前物理区域**寻找可容纳原尺寸的其他完整矩形空位；避免移动其他手工固定的 Tile。
3. 如果原尺寸在当前区域没有位置，则试着缩小到 **1×1**，寻找任意可用单元格。
4. 找到后安置；如果依然无空位，再按 Global/Page 的分流规则处理。

因自动安置而缩小，不应抹去用户曾设定的期望尺寸；后续在显式整理或允许的自动恢复时可尝试恢复。**自动恢复不能扰乱手动布局。**

### 6.2 Global 的分流

Global 找不到原尺寸或 1×1 位置时，将该项目视作**重新加入的收藏项目**：根据其类型所对应的默认页面组，依该组正常的新物品安置顺序进入分页。如果来源于 Global 变更，给出轻量、可追溯的去向提示。Global 永不因溢出创建续页。

### 6.3 Page 的分流与自动扩页

Page 当前区域找不到位置时：

1. 依**当前所属组**的逻辑顺序检查所有已有页面：起始页 → 续页 1 → 续页 2 → ……；检查每个候选页面时，优先原尺寸，必要时回退到 1×1。当前页已经检查过的无需重复。
2. 在任意已有页面找到空间就放进去，**不提前新建页面**。
3. 所有同组页面均放不下时，在该组末尾**自动创建紧邻的新续页**并放入新页。
4. 新增收藏项目也采用同样顺序：从该组第一页开始逐页搜索，满了才扩页。

注意：**组内搜索顺序是固定的**，避免每次刷新造成无序迁移。已有物品优先尝试保持当前所在页与位置，只有确实需要搬迁才跨页。

### 6.4 失败与边界情况

- `Page` 掩码为零格、所有合法区域不存在 1×1、配置文件无效、创建页面失败、物品无法稳定识别等情况下，不能形成无限扩页/递归。
- 无法执行上述自动流程时，明确告警；**这只是异常兜底，不是正常流程中的常驻“溢出收纳箱”**。
- 所有重排不依赖自己维护的队列，而是通过对于收藏的项目与被记录位置的项目作差来确定。在条件满足的时候重走“收藏新物品”流程。
- 预防同一物品在 Global 和 Page 被错误重复显示、重复执行、计数错乱。
- 自动分类不是背包物品转移，任何页面调整均不得更改 Skyrim 实际背包、法术知识、装备状态或收藏标记（除用户原本发起的使用/装备行为）。

## 7. 设置、持久化与迁移

- 持久化方案应当与基线一致。
- 至少保存：网格尺寸/行列/窗口大小位置、区域设置、各页布局、分组名称图标与顺序、分类默认去处、各类排序、导航偏好及手工固定状态。
- 执行者自行判断哪些应全局共享、哪些按存档隔离；不得错误地让一个存档的收藏引用污染另一存档。
- 从原版 TFM 配置/布局迁移时，优先保留可恢复的旧布局和收藏关系；第一次启用新布局有明确的迁移路径或备份。
- 配置写入应尽量具备中断安全性；保存失败时保留先前有效版本；提供备份与恢复入口。
- 至少提供撤销最近的布局操作；建议多步 Undo/Redo，尤其覆盖区域框选、批量整理、自动续页和整组移动。
- 取消收藏、背包物品消耗殆尽、法术移除、模组卸载、Form 变化等应正确清理/保留可恢复引用，不得在重新读档后产生幽灵 Tile。

## 8. 性能与兼容性

- 快速打开、关闭、切页、鼠标命中，不要因数百个收藏项而明显卡顿；延迟和内存占用应在实现过程中测量。
- 自动排序/填空不要每帧做全量扫描；避免布局变更引发无限循环或反复自动调整。
- 核对上游对应支持的 Skyrim SE/AE/VR、SKSE、Address Library、SkyUI、SKSE Menu Framework 等具体版本与依赖，不得以“编译通过”等同于“所有运行时兼容”。
- 兼容控制器/不同输入设备应尽量保持上游行为；不能因新 Q/E 绑定使其他输入路径完全不可用。
- 必须对用户实际游戏版本和模组整合环境做实机验证，发布前注明已验证的平台，而非臆测。

## 9. 交互决策清单（实现前做原型验证，不擅自改需求）

以下是需要执行者实测并写进交付记录的**待决小细节**，不是允许忽略的功能：

- 右键拖动位移的量化基准、起始点、拖动阈值、越界预览；`Shift+右拖缩小` 是否采用最终方案。
- 左拖移动与尺寸模仿的感应带宽度、停留反馈及冲突优先级；如果 A 的尺寸模仿后原位置放不下，应如何在预览中解释自动安置。
- 长按框选分区与长按拖动物品的区分（例如区域编辑模式只接受空白网格上的框选）。
- 非矩形 Global/Page 掩码中的寻找空位顺序，保证结果确定、不会越区。
- 用户对整组删除/排序/移动、续页清理的控制入口。
- 点击后原版“装备/使用/施法”的行为边界和 Q/E 冲突解决。

## 11. 必须通过的验收场景

1. 新收藏 10 个法术，全部从 1×1 开始；随设置修改网格单元大小、行列数和窗口面积，关闭再打开设置不丢失。
2. 从 Tile 内部右键向左、右、上、下及斜角拖动，各增加期望格数；不要求精确命中边缘；与右键短按有明确区别。
3. 将 A 拖近 B 内边界出现模仿反馈，确认后 A 与 B 尺寸一致且不覆盖 B；普通拖动不误触。
4. 框选一条顶边为 Global、其余为 Page；再框选出 L 形 Global；所有 Tile 均只占本区域允许的格。
5. Global 的图标保持固定；点击页点、按 Q/E，Page 内容变化；Q/E 既不误触使用也不关闭菜单。
6. 规则为“法术+卷轴+龙吼 → 魔法”，三种物品归入同组；用户手动改到别组的项目不被刷新搬回。
7. 当前 Page 缺少原尺寸空位，但有 1×1 空格，Tile 被缩为 1×1 并成功安置；其期望尺寸仍可恢复。
8. 当前组首页满，但第二页有空格，新项目进入第二页，**不新建第三页**。
9. 当前组所有页面均满，新项目自动产生连续的新页，且插在该组尾、其他组之前；导航图标/页点正确。
10. Global 变小后挤出的项目按分类进入相应 Page，不生成第二个 Global，不改变收藏标记。
11. 删除、移动或重命名一个组，再添加对应类型物品，系统有明确安全兜底，没有死循环、丢失或重复。
12. 全部网格划给 Global 造成 Page 零格时，新添加的分页物品不能无限创建空页；用户收到可恢复的异常提示。
13. 用户手动摆好的 Tile 不会因为新增收藏、排序刷新、重新读档而被任意移动。
14. 100+ 收藏项目连续新增、切页、读档与关闭菜单，不卡顿、不闪烁、不破坏原版使用逻辑。
15. 模组管理器停用/回退至基线版本，玩家存档依旧能够加载。

## 12. 对执行者的工作约束

- 不要在首轮就整体重写渲染框架；优先复用现有 UI、收藏同步和打包机制，在掌握依赖后按阶段替换。
- 用可测试的方式实现布局规则，特别是“同区域原尺寸 → 1×1 → Global 路由 / Page 组内逐页 → 续页”逻辑。
- 对每一阶段提交：变更摘要、构建/测试结果、尚未通过的验收场景、需要游戏内验证的项目；不宣称未经验证的功能已经可用。
- 直接给执行者设计与代码实现自由；**不把本文当作现成的数据结构、类设计或可直接编译的实现。**


**说明：** 以上“待决小细节”需在执行中完成交互验证；本规格已经锁定用户讨论的核心行为与溢出优先级，不应据此把关键需求变为可选。
